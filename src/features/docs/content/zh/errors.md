# 错误处理

API 错误响应通常遵循 OpenAI 格式：

```json
{
  "error": {
    "message": "Human-readable description",
    "type": "invalid_request_error",
    "code": "model_not_found"
  }
}
```

## 常见 HTTP 状态码

| 状态码 | 含义 | 常见原因 |
|--------|------|----------|
| `400` | 请求无效 | 缺少必填字段、JSON 格式错误、模型不存在 |
| `401` | 未授权 | API Key 缺失或无效 |
| `403` | 禁止访问 | Key 被禁用、模型不在允许列表、余额不足 |
| `429` | 请求过多 | 触发速率限制，请退避重试 |
| `500` | 服务器错误 | 上游异常，可稍后重试 |
| `502` / `503` | 网关/服务不可用 | 渠道故障或维护中 |

## 错误类型 (type)

| type | 说明 |
|------|------|
| `invalid_request_error` | 客户端请求参数问题 |
| `authentication_error` | 认证失败 |
| `permission_error` | 权限或配额不足 |
| `rate_limit_error` | 速率限制 |
| `server_error` | 服务端或上游错误 |

## 重试建议

1. **`429`** — 使用指数退避（如 1s、2s、4s），并检查响应头中的限流信息
2. **`500` / `502` / `503`** — 有限次数重试，避免无限循环
3. **`400` / `401` / `403`** — 修正请求或密钥后重试，通常不应自动重试

## 调试技巧

- 在控制台 **使用日志** 中查看完整请求记录
- 确认 `{baseUrl}` 与 Key 权限、模型名称拼写正确
- 流式请求中断时，检查网络超时与代理配置
